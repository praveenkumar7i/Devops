# Exercise 9: Jenkins Multi-Stage Pipeline

## 1. Project Overview

This exercise demonstrates how to automate the build, testing, deployment,
and verification of a Python Flask web application using Jenkins CI/CD.

The project uses a declarative `Jenkinsfile` to define a pipeline containing
five stages. Each stage performs a specific task, and Jenkins displays the
result of each stage in the pipeline execution view.

The Flask application provides a simple HTTP endpoint that returns a
predefined response. Automated tests verify both the application logic
and the deployed application's HTTP response.

## 2. Objectives

- Understand Jenkins declarative pipelines.
- Automate Python dependency installation.
- Create an isolated Python virtual environment.
- Execute automated unit tests through Jenkins.
- Copy application files into a deployment directory.
- Start the Flask application as a background process.
- Verify the deployed application using an HTTP request.
- Understand how CI/CD stages work together.

The project implements a small Flask web application.

### Application Endpoint

| Property | Value |
|---|---|
| HTTP method | GET |
| Route | `/` |
| Default port | `5000` |
| Host binding | `0.0.0.0` |
| Expected HTTP status | `200 OK` |
| Expected response | `Hello, Jenkins Multi-Stage Pipeline!` |

## 6. Jenkins Pipeline Architecture

The Jenkinsfile defines the following execution sequence:

```text
Pipeline Start
      |
      v
  1. Build
      |
      v
  2. Test
      |
      v
  3. Deploy
      |
      v
  4. Run Application
      |
      v
  5. Test Application
      |
      v
 Pipeline Result
```

Each stage must complete successfully for the pipeline to reach its final
success state. A failing command causes the relevant stage and pipeline
to fail.

## 7. Detailed Explanation of Pipeline Stages

### Stage 1: Build

**Purpose:** Prepare the Python environment and install dependencies.

Activities:

1. Create a virtual environment named `.venv`.
2. Upgrade pip inside the virtual environment.
3. Install the packages listed in `requirements.txt`.

Expected outcome: The required Python dependencies are installed and
available to subsequent pipeline stages.

### Stage 2: Test

**Purpose:** Verify the application using automated unit tests.

Activities:

1. Discover test files matching `test_*.py`.
2. Execute the tests using Python's `unittest` framework.
3. Check the HTTP response generated by the Flask test client.
4. Verify the expected status code and response text.

Expected outcome: The unit test passes when the application returns the
expected result.

### Stage 3: Deploy

**Purpose:** Prepare a deployment directory containing the application files.

Activities:

1. Create the `python-app-deploy` directory.
2. Copy `app.py` into the deployment directory.
3. Copy `requirements.txt` into the deployment directory.

Expected outcome: The application files are available in the deployment
directory inside the Jenkins workspace.

Note: This is a simulated, workspace-based deployment. It does not deploy
the application to a separate production server or cloud platform.

### Stage 4: Run Application

**Purpose:** Start the deployed Flask application.

Activities:

1. Change to the deployment directory.
2. Stop a previously recorded application process, if present.
3. Start Flask using the Python interpreter from the virtual environment.
4. Redirect application output to `app.log`.
5. Record the process ID in `app.pid`.
6. Check whether the process remains running.

Expected outcome: The application starts as a background process on the
Jenkins agent and listens on port `5000`.

### Stage 5: Test Application

**Purpose:** Verify the running application through HTTP.

Activities:

1. Send an HTTP GET request to `http://127.0.0.1:5000/`.
2. Retry the request if the application is not immediately ready.
3. Verify that the HTTP status is `200`.
4. Verify that the response body matches the expected message.
5. Fail the stage if the application does not respond correctly.

Expected outcome: Jenkins confirms that the deployed application responds
with the correct HTTP status and message.

## 8. Prerequisites

Before executing the pipeline, ensure that the following requirements
are satisfied.

| Requirement | Description |
|---|---|
| Docker | Installed and running if Jenkins is containerized. |
| Jenkins | Accessible through the Jenkins dashboard. |
| Python 3 | Available on the Jenkins build agent. |
| pip | Available through the Python installation. |
| venv support | Required to create the `.venv` environment. |
| Git | Required when retrieving the project from source control. |
| Network access | Required to download Python packages when not cached. |
| Jenkins Pipeline support | Required to execute the declarative Jenkinsfile. |

The Jenkins agent must support Linux shell commands because the pipeline
uses `sh`, `mkdir`, `cp`, `nohup`, and other Unix-style commands.

Installing Python or pip on the Windows host does not automatically install
them inside the Jenkins container or on a separate Jenkins agent.

## 9. Local Execution and Verification

The following commands are intended for the Windows PowerShell terminal
opened in the project directory.

### Step 1: Check Python and pip

```powershell
python --version
python -m pip --version
```

### Step 2: Install project dependencies

```powershell
python -m pip install -r requirements.txt
```

### Step 3: Execute automated tests

```powershell
python -m unittest discover -s . -p "test_*.py" -v
```

Expected test result:

```text
test_home ... ok

Ran 1 test

OK
```

The exact timing and warning messages may vary by environment.

These commands validate the application locally. They do not execute the
Jenkins pipeline.

## 10. Configure the Jenkins Pipeline Job

1. Open the Jenkins dashboard.
2. Select **New Item**.
3. Enter a job name such as `Python-MultiStage-Pipeline`.
4. Select **Pipeline** and create the job.
5. Configure the Pipeline definition according to the repository setup.
6. Save the configuration.
7. Select **Build Now**.
8. Open the build and inspect its stage results and Console Output.

### Source Control Configuration

When using Pipeline script from SCM:

| Setting | Configuration |
|---|---|
| Definition | Pipeline script from SCM |
| SCM | Git |
| Repository URL | URL of the GitHub repository containing the project |
| Branch | The branch containing the committed Exercise 9 files |
| Script Path | Path to the Exercise 9 `Jenkinsfile` relative to the repository root |

If the repository root is the `Devops` directory and the exercise is
stored under `Exercises`, the script path may be:

`Exercises/exercise-9-Jenkins-Multi-Stage-Pipeline/Jenkinsfile`

Use the actual repository structure when configuring this field.

If the exercise folder itself is the repository root, use `Jenkinsfile`.

## 12. Troubleshooting

| Problem | Possible Cause | Suggested Action |
|---|---|---|
| Python command not found | Python is unavailable on the Jenkins agent. | Install Python or use an agent image containing Python. |
| pip module not found | pip is unavailable in the agent environment. | Install pip for the relevant Python interpreter. |
| Virtual environment creation fails | The venv package is missing. | Install the appropriate virtual-environment support. |
| Dependency installation fails | Network, package, or Python compatibility issue. | Inspect the pip error in Console Output. |
| Unit tests fail | Incorrect response, import error, or dependency mismatch. | Run the test locally and inspect the traceback. |
| Deployment directory is missing | The Deploy stage did not complete. | Inspect the stage logs and workspace path. |
| Flask process exits | Application startup or dependency error. | Inspect `python-app-deploy/app.log`. |
| HTTP test fails | The application is unavailable or returns an unexpected response. | Check the Run Application logs and port `5000`. |
| Jenkins cannot find Jenkinsfile | Incorrect source-control Script Path. | Verify the repository layout and Jenkinsfile location. |
| `sh` step fails on Windows agent | Pipeline uses Linux shell commands. | Use a Linux Jenkins agent for this Jenkinsfile. |

## 13. Limitations and Notes

- The deployment is restricted to the Jenkins workspace.
- The application is not deployed to an external production environment.
- The pipeline requires a compatible Linux-based Jenkins agent.
- Python dependencies must be installable in that agent's environment.
- The Flask application uses port `5000`, which must be available to the process.
- The application process is started in the background; this exercise does
  not implement production process supervision or automatic cleanup.
- The virtual environment and deployment files are generated during builds.
